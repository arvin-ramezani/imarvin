# UI Art Director

## Host and source resolution

Read the bundled [Work source access guide](references/work-source-access.md) first. In a verified Codex checkout, retain the repository-relative links below. In an individually installed ChatGPT Work package, resolve external workflow/specification/cross-skill links through that guide at verified GitHub SHAs; never assume sibling files exist or substitute remembered requirements.

## Load and scope

Read the [shared workflow and authority map](../../../docs/engineering/image-first-design-workflow.md) and [design craft](references/design-craft.md). Verify current source SHA, screen issue and relevant canonical requirements; do not rely on remembered Home order or legacy Work layouts.
Take the user task, screen/state coverage, P18 fixture content and any existing approved visual language as inputs. If no screen is selected, follow the next authorized bounded #58 screen; do not create every future sub-issue.
Stay in design direction: create no application code, prototype, image assets or approvals through this skill. Route authorized actual mockup generation to `$spec-to-ui-image`.

## Explore deliberately

1. State the primary audience/task and first-reading priority, with scoped requirement IDs. Separate fixed behavior from design freedom and unresolved choices.
2. Inspect existing approved sources when available; read the registry's revision and approval evidence. Distinguish historical aesthetic approval from approval of a new image.
3. If references are available, inspect a small relevant set and record source URLs plus extracted principles. Do not copy branded layouts or block work merely because external references are unavailable; disclose that limitation.
4. For initial direction, propose **three** named compositions with materially different balance, work scale, density or type hierarchy. Keep required information order, content, theme and viewport comparable. Never offer three palette swaps.
5. Name each direction's signature move, user benefit and cost. Apply Signal Studio's work-led asymmetry, hierarchy, restrained blue and purposeful shapes; reject repetitive card walls and ornamental effects as a substitute for composition.
6. Sketch desktop-to-mobile transformation in words: what stacks, wraps or changes emphasis while preserving reading order and actions. Include Light/Dark and no-media implications; do not invent new mobile behavior or controls.
7. Check each against the same fixed requirements and fixture data. Replace a redundant or noncompliant option before handing off. Later screens should reuse the selected language; do not reopen art direction without a real conflict or owner request.

Treat familiar patterns as tools, not forbidden objects. Novelty must improve understanding or express identity within approved behavior. Do not force an editorial résumé, a new palette/concept, hidden navigation or new Story templates.
If navigation/editor/media behavior remains open, return `OWNER DECISION REQUIRED` with exact authority and the smallest blocking question. Mark dependent variants deferred; continue independent composition work. Do not ask for approval of every spacing choice.

## Output

Return a compact direction brief:

- Source SHA, issue, audience/task, canonical IDs and approved/open boundaries.
- Shared fixture dataset, viewport/theme/state and existing visual sources consulted.
- A table: direction / composition axis / signature move / user benefit / cost / mobile and no-media implication.
- Reference URLs and extracted principles, or unavailable-reference limitation.
- Requirements check, deferred variants and next image-generation brief.

Keep directions `PROPOSED`. A selected concept is not exact-image approval. Pass the chosen direction, or all three for comparable image exploration when requested, to `$spec-to-ui-image`; never claim a prose brief is an actual mockup.
